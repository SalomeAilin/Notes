正式选名前的停止条件

  1. 用户先从候选中确定少量偏好，避免无边界检索。
  2. 由权利人登录 CNIPA，至少对相关文字及近似组合做第 9 类、第 42 类查询并保存证据。

  4. 只有通过上述门禁后，才修改 CFBundleDisplayName 和界面文字；不得顺手更改稳定技术身份。

二、百度网盘安全接入边界

OAuth 公开证据

模式官方公开要求当前决定
授权码换 token 和 refresh 均要求 client_secret。不能在 iOS 包内直连换 token。
设备码取 device_code 只需 client_id，但轮询换 token 和 refresh 仍要求 client_secret。不是无密钥 token 流程。
简化模式不要求 secret，但 access token 直接进入回调片段且不支持 refresh。不作为与 broker 等价的正式方案。
官方 iOS 基础模块公开示例直接接收 secretKey 来换取和刷新 token。SecretKey 留在可信服务端。

本轮检查当前官方授权/iOS 文档和官方 Go SDK，没有发现 PKCE、code_challenge、code_verifier 或 S256。这只证明当前公开资料没有公开或实现 PKCE，不能外推为服务端必然拒绝未文档化参数。

保留 broker 边界。SecretKey、refresh token 和 refresh token 的原子轮换由服务端处理；iPad 只通过 ASWebAuthenticationSession 与真实 HTTPS broker 交互，并使用强 state、一次性票据和可验证回调。Notes 与自有 broker 之间可以另行设计 PKCE，但不得把它称作“百度 PKCE”。

什么才算“远端内容已证明”

创建文件接口只返回 fs_id、path、size、MD5 等元数据，没有“服务端重新读取持久化对象并签发 SHA-256 字节证明”的公开契约。因此 create 成功、列表命中或 MD5/size 一致都继续标记为“内容未证明”。

可实现的强核对链：用 fs_id 调用查询文件信息取得 dlink，再按下载接口鉴权流式读取全部远端字节；在设备端计算 SHA-256，只有与本地备份清单的 archiveSHA256 完全一致时才可进入 contentVerified。

百度功能的发行门禁

  • 没有生产 broker、正式回调身份和真实账号验收时，不展示“已连接”或上传按钮。
  • App、Info.plist、xcconfig、Keychain、日志和 Git 历史不得包含 client secret。
  • 上传 create 之后继续保留本地不可变对账记录；远端字节强核对成功前不得核销、宣称完成或授权盲重传。
  • 下载核对只接受 HTTPS，限制长度，使用短期凭据，不持久化 token；失败、取消、重定向异常或哈希不符都保持“未验证”。
  • 真实账号联调还需验证授权目录、配额、路径冲突、前后台行为、限流、撤销授权和账号切换。
