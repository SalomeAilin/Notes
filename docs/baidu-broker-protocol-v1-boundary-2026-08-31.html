百度 broker v1 离线协议边界

首次冻结：2026-08-31｜候选域名预检补充：2026-09-01（Asia/Shanghai）｜性质：格式与状态机门禁，不是可用的百度账号连接

结论：仓库只新增了纯离线、休眠的 wire/state 基础。它不会发起网络请求、打开授权页面、签发生产凭据、写入 Keychain 或展示“已连接”。

已经冻结的合同

项目v1 合同
消息类型授权开始、回调、兑换请求、凭据响应、错误响应分别使用五个精确 schema，禁止跨阶段喂入。
随机绑定attempt、state、verifier、ticket 都是 32 字节随机值的规范无填充 base64url；challenge 为 base64url(SHA256(base64urlDecode(verifier)))。
解析边界回调只接受不超过 1 KiB 的原始 ASCII query，不做 percent/plus 宽松解码；响应只接受不超过 2 KiB、键和值均为字符串且无重复键的严格 JSON。
时间边界单次尝试最多 10 分钟；收到 ticket 后至响应完成的总兑换窗口最多 60 秒。期限使用单调时钟，凭据绝对到期还采用会话内防壁钟回拨的保守时间。
重放边界进程内最多保存 256 个 ticket 指纹和 512 个 attempt/state/challenge 绑定指纹；不驱逐，达到上限即失败关闭。

明确没有实现

  • 没有真实 HTTPS broker origin、路由、TLS/响应身份验证或服务器部署。
  • 没有 ASWebAuthenticationSession、正式回调注册、URL Scheme 或把 raw query 提升为来源可信消息的 shipping 构造入口。
  • 没有 broker 端原子 ticket 单次消费、跨重启重放存储、稳定账号绑定、refresh token 轮换、撤销授权或生产凭据发行器。
  • 没有真实百度账号、CDN、撤销/换号、前后台传输或 iPadOS 27 端到端验收。
为什么仍需 broker：当前检查到的百度官方 Go SDK 授权码换 token 与 设备码换 token 源码都需要 client_secret。这不证明百度服务端不存在未公开的 PKCE 能力，但不足以把密钥安全地放进 iOS public client。

候选域名本地预检

正式域名尚未写入工程前，可以运行：

./scripts/check-baidu-broker-origin.zsh --origin "https://broker.domain-you-control.com"

请把示例替换为你实际控制的小写 ASCII 域名。该命令拒绝账号、端口、路径、参数、片段、本机/IP/保留测试地址、视觉混淆编码和百度官方域名。它不联网、不修改工程、不写配置，也不注册回调或授权入口。

边界：通过只说明地址满足当前最小格式规则，不证明域名所有权、TLS、服务部署、响应身份或百度授权可用。正式接入仍须完成这些验证以及回调、单次票据、撤销和真实账号验收。

下一道门禁

只有确定自有 broker 的正式域名、回调身份、响应真实性方案、服务器端原子票据存储和账号生命周期后，才允许设计网络适配层；完成真实账号与 iPadOS 27 验收前，不开放用户入口。
