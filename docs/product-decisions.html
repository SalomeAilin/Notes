产品命名与百度网盘接入

结论先行：“墨记”只能继续作为未公开开发包的临时名，不适合公开测试或上架；候选名称暂按“纸上屿”优先、“字成林”备选继续核查。百度网盘先走系统文件通道，直连版本再引入只保管凭据的小型 HTTPS 服务。

快照日期：2026-08-30 基线：0.2.0 (2) iPadOS 17+ 决策分支：docs/product-decisions

1. “墨记”为什么有风险

这是已经确认的同类市场重名，不只是抽象的法律担忧。 中国区 App Store 已有“墨记-精美日记本·笔记本”，并有大量公开评分；另有“Ink Note - 墨记”和“留白·墨记”。因此继续公开使用会显著增加来源混淆、商店名称不可用和商标争议风险。

这个名称最初只是开发阶段对“墨水书写＋记录”的直观概括，没有经过市场清查，不代表正式品牌决定。当前仓库 README 已把它标注为临时显示名，Bundle ID 也刻意保持为技术身份。

公开证据：App Store：墨记-精美日记本·笔记本、App Store：Ink Note - 墨记、App Store：留白·墨记。

公开网页和应用商店筛查只能排除明显冲突，不能替代商标近似检索或法律意见。正式采用前仍需在国家知识产权局商标网上查询中按相关类别做文字、读音和近似查询；该官方系统本身也提示数据可能滞后、结果仅供参考。

2. 候选名称初筛

本轮以中文公开网页、Apple 中/美/港/台 App Store 官方 Search API 和 GitHub 公开索引做精确词检索。风险分级只表示“是否发现明显同名/近名”，不是商标可注册性结论，也不代表 App Store Connect 已预留名称。

3. 更名不会破坏现有笔记的边界

可以改：展示层

  • CFBundleDisplayName 主屏名称
  • App 图标、README、商店文案
  • 备份类型的可见描述与文件名前缀
  • 正式名称确定后，百度授权页展示文案

首轮必须保持：兼容身份

  • Bundle ID：com.salomeailin.InkNotes
  • 本地目录：Application Support/InkNotes
  • 备份 UTI、.notesbackup、MIME 与 INKNOTE\0
  • formatVersion = 1 与 schemaVersion = 1

只改显示名称不会形成新的沙盒；改 Bundle ID 则会成为另一款 App，旧笔记会留在旧沙盒里，新 App 看起来像空库。改本地目录也会形成两套数据。因此首次品牌更名不重命名 Xcode project、target、scheme、Swift 模块和源目录。

安全提交顺序

  1. test(compat): pin persisted app and backup identities：已在 test/brand-compatibility 实现；v1 黄金备份含真实 PencilKit 笔画，并锁定 Bundle ID、目录、UTI、扩展名和 magic。
  2. feat(brand): update user-facing app identity：只改显示层，版本建议递增到 0.2.1 (3)。
  3. docs(brand): document rename compatibility contract：记录兼容边界与覆盖安装验收。

兼容门禁已在 Xcode 27 beta 下通过 26 个测试及 Debug/Release generic iOS 构建，并经独立复核确认无 blocker/major；提交为 7fb50ff、1368a95、789cd97 与 bdcc61f。真机覆盖安装前仍必须先从 0.2.0 导出一份可识别的备份，保留旧 App、不卸载；覆盖后检查旧笔记、书写、重启读取和旧备份恢复。失败时用 git revert 和更高 build 覆盖回滚，不重写已推送历史。

4. 百度网盘：两阶段接入

阶段 A：系统文件通道（现有 0.2.0 基础）

应用已经能够通过系统文件导出、导入和分享 .notesbackup。如果百度网盘 App 在 iPadOS 27 上提供可用的系统文件位置，用户即可在导出时选百度网盘、恢复时从百度网盘选择文件。这一路径不需要 AppKey、SecretKey、OAuth 或自建服务，是当前优先真机验收项。

系统文件通道是否在当前百度网盘版本和 iPadOS 27 上完整可用，必须真机确认；代码具备入口不等于第三方文件提供器已经通过运行验收。

阶段 B：应用内百度直连

1. iPad以已证明的安装会话打开系统网页认证
2. Broker固定回调地址、校验 state，再用 SecretKey 换 token
3. KeychainiPad 仅暂存 Access Token，不保存 Refresh Token
4. 百度网盘备份文件由 iPad 直接上传至应用目录
5. 恢复下载后校验大小、SHA-256 和 PencilKit，再恢复为副本

百度官方的授权码流程要求使用 SecretKey 换 token，并明确适合有 Server 端的应用；当前公开文档没有列出 PKCE，因此不能把 SecretKey 放进可被提取的 iPad App。无服务端的简化模式无法刷新 token，不适合作为长期备份连接。参考：授权码模式、简化模式、iOS OAuth 接入。

安装会话不是硬编码口令。 公开版本由服务端发挑战，iPad 使用 Apple App Attest 生成并证明每安装实例的密钥，服务端验证后才签发短期、可轮换、可吊销的安装会话；敏感请求再附带由同一密钥生成的 assertion。会话自然过期后，同一已登记密钥可凭新挑战恢复；连续 90 天没有成功恢复则删除孤立安装记录和 Refresh Token。重装、设备迁移或 Keychain 丢失会同时失去原密钥和安装标识，不能恢复旧连接，必须重新登记并重新授权百度。App Attest 不受支持或验证失败时，禁用直连，不静默降级为共享密钥。参考 Apple 的应用完整性指南。

Broker 只保管

  • 百度 SecretKey
  • 百度 Refresh Token
  • 服务端加密主密钥、会话签名密钥
  • App Attest keyID、公钥、签名计数器与必要验证元数据

Broker 不接触

  • 手写内容和完整 .notesbackup
  • 笔记标题、页面预览和 PencilKit 数据
  • 百度账号密码
  • 客户端日志中的 token、授权码或下载链接

首版直连只允许用户主动上传不可变备份、列出备份、主动下载并“恢复为副本”；不做自动覆盖、远端删除、笔记级双向同步或冲突合并。百度把应用权限限制在 /apps/{正式应用名}；客户端再把产品路径固定为其下的 Backups。由于文件直传，Broker 看不到百度请求，不能强制客户端的子目录规则；被篡改的客户端仍可能在百度授予的应用目录范围内滥用 Access Token，这是直传方案的残余风险。

百度对新应用的目录、权限和配额有限制。未提交或未通过上线审核时仅用于开发者测试，不能直接发布线上使用；公开发布必须完成审核。参考创建应用、权限与配额、上线审核。

5. 百度直连的安全与兼容门禁

风险控制验收证据
OAuth CSRF / code 注入高熵 state、绑定安装会话、精确 redirect URI、一次性事务与短时限错误 state、过期 code、重放均被拒绝
伪造或遗失安装会话App Attest 挑战、服务端保存 keyID/公钥/计数器、版本化字节级请求哈希、密钥绑定、轮换与吊销；过期会话可由同一密钥恢复，孤立连接 90 天后清理伪造/过期 attestation、assertion 重放、错误哈希、重装后的旧会话均被拒绝；TTL 清理删除 Refresh Token
Refresh Token 并发失效每个连接单飞刷新；新 token 原子替换；失败后停止循环重试并发刷新测试只有一次上游请求
凭据泄漏SecretKey/Refresh Token 只在服务端加密保存；Access Token 用 kSecAttrAccessibleWhenUnlockedThisDeviceOnly 存入 Keychain；URL、Header、302 Location 全面脱敏设备迁移不带走 token；Git、IPA、broker 日志、崩溃报告秘密扫描
被篡改客户端滥用路径百度应用目录是上游权限边界；正常客户端固定 Backups 子目录并拒绝分隔符，但 Broker 无法强制直传请求客户端路径测试通过，并在风险说明中保留该残余风险
损坏或恶意备份临时文件、32 MiB 总上限、8 MiB 单页上限、SHA-256、结构与 PencilKit 校验损坏、超限、截断文件不能进入恢复
中断与重复上传分片状态、幂等 ID、仅在 create 完成后展示，默认远端重命名断网、锁屏、前后台和重复提交测试
云端明文泄露当前 .notesbackup 未加密；阶段 A 每次导出明确提醒，阶段 B 上线前必须选定并验证客户端加密/恢复密钥方案，或要求用户逐次确认剩余风险账号失陷威胁测试、跨设备恢复演练、密钥丢失演练与用户确认文案
断开后 Access Token 残留立即删除 Broker 的 Refresh Token 与本机 Keychain 项；若百度没有可用撤销接口，已签发 Access Token 可能持续到自然过期界面明确残余有效期；再次调用 Broker 取凭据必须失败

百度公开的 iOS OAuth SDK 最新说明只到 Xcode 26 / iOS 26，没有 iPadOS 27 兼容承诺；网盘 SDK 页面也没有 iPadOS 27 的完整验证信息。因此首版建议使用系统网页认证与 URLSession 调官方 REST API，不引入闭源 SDK。参考：OAuth SDK 版本页、网盘 iOS SDK。

当前 iPadOS 27 证据仅到已签名构建：设备已配对且开发者模式开启，但可信 tunnel 仍不可用；安装、启动、Apple Pencil、百度 File Provider 和直连均未通过真机验收。后续门禁包括授权/取消/回跳/重连、4 MiB 分片和 32 MiB 边界、前后台/断网/锁屏续传、上传后列表和下载、SHA-256 校验与副本恢复、token 临近过期并发刷新，以及秘密扫描。未完成前不能称为“iPadOS 27 兼容”或“百度网盘直连可用”。

6. 现在需要的一个决定

请选择更名方向：当前建议“纸上屿”，备选“字成林”。确认后由商标代理人完成至少第 9、42 类的相同及近似检索并留存书面结果；用户自行查询仅作辅助。之后再做 App Store Connect 名称检查；通过后才提交显示层更名。在此之前不以“墨记”创建百度开放平台应用。

不需要等待名称决定的工作可以继续：在 iPad 重新连通后，先完成 0.2.0 的安装、Apple Pencil 书写、备份导出/恢复，以及百度网盘系统文件位置测试。
